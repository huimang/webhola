## HTTP 服务扫描

- 使用 Windows `GetExtendedTcpTable` 枚举 IPv4 / IPv6 TCP 监听端口及 PID；通过本机临时 HTTP 服务验证了实际端口和所属进程的识别，再完成 HEAD 探测。
- HTTP 200 / 301 / 401 / 404 / 405 / 500 均能识别；确认不跟随重定向、不使用环境代理，SSH 和无响应服务不会列为 HTTP。
- 确认重复地址去重、扫描取消、探测超时、原生监听表长度校验与端口字节序。
- 原生 UI 交互测试通过服务下拉框选择结果，确认端口与 loopback 联动；IPv4、IPv6（含 scope）、所有地址及无法匹配地址均有测试。手动改端口后解除原服务选择，最小窗口下新增控件均可见。
- 全部 23 项顶层测试通过（含真实 TShark 集成与可选预览），`go vet` 和 Windows 构建通过。扫描界面布局预览：`.build/http-service-scan-preview.png`。
- 需要指定 Host 或不接受 HEAD 的服务仍可能漏检，保留手动输入；本轮未测试大量实际开发服务并行运行的长期表现。

- 每条请求提供“重新发送”，保留原记录并创建独立置顶记录，记录响应、耗时与失败原因。
- 本机 HTTP 服务验证 POST、二进制正文、Host、Cookie、Authorization、重复头部和查询参数；确认仅发送一次且不跟随重定向。

- 验证截断／缺失／长度不符／压缩编码正文拒绝重发，以及失败状态与响应预览限制。
