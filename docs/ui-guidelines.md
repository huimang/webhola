# Webhola UI 规范 · 0.2.1

Webhola 是面向网站开发者的本地桌面工具箱。沿用 MediaHola 当前的 Go + MyGO 原生方案、浅色／深色界面和青蓝品牌体系；首个工具为 HTTP 监听。产品名展示为 Webhola，字标使用小写 `webhola`。

## 唯一品牌标识

`assets/brand/webhola-icon.svg` 是唯一图形标识：青绿到蓝色的圆角方块，白色代码括号包围双向箭头。括号表示网站开发，双向箭头表示请求与响应。`webhola-logo.svg` 只将同一标识与字标组合，不增加另一套图形。与 MediaHola 保持同系列的轮廓和渐变，内部符号独立。

- 图标源画布 512 × 512，主体 464 × 464，圆角 124；最小显示尺寸 24 DIP。
- 四周留白至少为图标显示宽度的 1/8。禁止拉伸、旋转或单独改变内部符号比例。
- 渐变 `#39DDC1 → #17BDCB → #4488F5` 只用于品牌标识。文字与控件使用对比度更高的实色。
- 字标使用 Segoe UI / Inter / Arial，深蓝 `#172D46`，字重 650。SVG 保留可编辑文字，PNG 用于固定外观分发。

## 字体与尺寸

- 系统 UI 字体：中文使用系统回退字体，基准字号 13 DIP（对齐 IDEA 默认值）；字标 22、页面／空状态标题 18、详情与弹窗标题 16、面板标题 14、正文 13、辅助信息 11–12 DIP。
- HTTP 头部与正文使用 Consolas 等宽字体，13 DIP；支持选择、复制、滚动，默认只读。
- 基础间距 4 DIP；常用间距 8 / 12 / 16 / 20 / 24 DIP；卡片圆角 8 DIP。
- 默认窗口 1200 × 820 DIP。0.2.1 采用桌面横向布局，建议宽度至少 1100 DIP；窄屏自适应留待后续版本。
- 焦点环 2 DIP，颜色为主色；保留原生键盘焦点与文本编辑控件的复制行为。

## 页面结构

主页面不展示顶部品牌区域，直接从扫描与监听工具栏开始。原生菜单依次为“文件 / 视图 / 帮助”；“文件”下依次为“设置…”、分隔线和“退出”。“设置…”打开包含 Java / Arthas 配置的设置面板；“帮助 → 关于 Webhola”打开独立模态窗口，展示标识、简介、版本与功能范围。清空记录位于左侧请求列表标题旁。状态说明紧邻控件，解释缺少依赖、无网卡、权限错误与正在停止等状态。

Body 默认显示原文，正文顶部固定提供“原文／格式化”切换及“全屏查看”按钮。原文视图最多显示前 1 KiB，超出时提示，避免超大正文或二进制十六进制内容卡住界面。JSON 格式化使用两空格缩进并高亮：键名蓝色、字符串深绿色、数字棕色、布尔值／null 紫色。支持 `application/json`（含 charset）与 `application/*+json`。只读查看器提供行号、滚动和复制；捕获原文保持不变，格式化失败、截断或嵌套超过 128 层时显示原文并提示，格式化按钮禁用。

Content-Type 为 `image/*` 时，正文默认显示图片元信息（格式、尺寸、分辨率与大小），不展示二进制原文，工具栏只保留“预览”按钮，点击后在正文区域按原始比例显示图片。解码失败或图片尺寸过大时保留元信息并给出提示，不展开位图。

全屏查看打开带独立阅读状态的原生全屏窗口，保持打开时的正文内容和初始视图模式；顶部保留原文／格式化（图片仅预览）、退出按钮及 Esc 退出提示。退出后返回主界面，主界面的选择与视图模式保持不变。全屏入口对所有非空正文显示，长内容出现滚动时始终可用。

HTTP 监听工具栏第一行为扫描／停止扫描按钮和服务下拉框，同一端口只显示一项，列表显示端口、服务类型、进程和 PID；同一进程的不同端口分别列出。第二行为网卡选择、HTTP 端口和监听操作，不再显示额外的端口或监听地址下拉框。内部保留同端口全部绑定，捕获仅按当前网卡和 TCP 端口过滤。多地址或通配地址保留当前网卡，不能默认切到 loopback；手动网卡选择在切换和刷新后保留。监听期间禁止切换捕获目标；扫描只在点击后执行并提示 HEAD 探测请求。

工作区左侧 390 DIP 为请求列表，右侧自适应为详情；列表和正文各自滚动。左侧包括搜索、可见数量、方法、URL、时间、状态码、响应耗时和正文大小。右侧包括完整 URL、客户端／服务端、TCP 流编号、请求／响应页签、起始行、Headers 与 Body。

- 空列表说明如何发起第一条请求，搜索为空说明没有匹配项。
- 尚未收到响应时明确显示“尚未捕获到最终响应”，不伪造 200 状态或耗时。
- 100 等临时响应保留提示，最终响应才标记完成；101 为协议切换结果，升级后的流量不解析。
- 清空记录保持监听继续；停止监听保留记录；重新开始开启新会话并清空旧记录。
- 选中行使用浅青背景，方法使用深青色，不为每种 HTTP 方法引入不同装饰颜色。
- 最多保留最近 1000 条请求，底部显示淘汰数量；正文预览每条最多 64 KiB，截断必须标注。
- 示例数据必须显著标记，不能与真实监听状态混淆。

## 后续工具扩展

新功能沿用统一品牌、主题、状态语义和间距。工具数量增加后再添加工具导航，0.2.1 不展示无功能的占位入口。

## JVM 调用监控

仅在扫描并选择已确认的 JVM 服务时显示入口。窗口顶部使用搜索输入框配合 URL 路由下拉框，选择后填写类、方法和 ClassLoader；保留 watch、trace、停止与断开操作。主工作区与 HTTP 监控一致：左侧 350 DIP 为调用列表，右侧为当前调用详情，各自滚动。

每次 watch / trace 命中生成独立记录，显示序号、观察模式、方法、路由、时间、耗时及完成／异常状态；新记录不抢走当前选择。切换路由显示相应历史，清空不改变观察目标。历史最多 100 条或约 16 MiB。

watch 详情提供请求参数、响应结果、异常和原始结果页签；JSON 默认格式化高亮，支持切换原文、只读复制和独立全屏快照，Esc 退出。trace 详情提供调用树和原始结果，节点展示类、方法、行号、耗时与次数，支持下探。无法可靠解析的结果仅展示原文，达到预览上限时提示截断。界面说明这是方法级观察，路由名称并不证明一次调用来自某条唯一 HTTP 请求。所有新增文案使用中英文资源键。

## 扫描等待状态

扫描 Web 端口、Arthas Attach 与路由扫描开始时立即显示独立的模态加载窗口，包含转动指示、当前状态及取消按钮。Attach 的加载状态持续覆盖后续路由扫描，已连接后的重新扫描也显示。窗口在成功、失败、超时或取消清理完成后自动关闭，详细结果及错误保留在原页面；取消和关闭按钮停止任务，清理期间显示“正在停止”并防止重复取消。所有文案提供中英文资源。

Trace 已有调用结果时，等待后续请求不能禁用下探。点击有效 Java 方法的下探按钮后，先停止并清理当前观察会话，再查询目标方法的 ClassLoader 并选中方法；已有调用历史保留，用户可继续点击 watch 或 trace。切换清理期间禁止重复下探，扫描或查询等其他操作忙碌时仍禁用下探。
