# HTTP 抓包、服务发现与重发

本页记录现有桌面应用的详细行为和技术限制。基本操作见项目 README。

## HTTP 监听

通过平台抓包适配器被动捕获指定网卡、指定 TCP 端口的明文 HTTP/1.x。Windows 使用 Npcap，Linux 使用 AF_PACKET，macOS 使用系统 BPF；公共层使用 gopacket 重组 TCP 流并解析 HTTP 消息。抓包不占用被监听端口，也不设置系统代理。

左侧显示请求列表：方法、URL、时间、状态、耗时、正文大小，可按方法／URL／状态码／IP 搜索。选中后右侧显示请求与响应起始行、头部和正文，支持复制。保留临时响应，支持同连接上的多次请求与 IPv6。

每条记录提供 **重新发送** 按钮。点击后使用原方法、URL、Host、请求头（含 Cookie / Authorization）和捕获正文发起一次新的 HTTP 请求；原记录保留，新记录置顶并标记“重发”，显示响应、耗时或失败原因。停止监听后也可重发；监听期间通过连接地址避免被动抓包重复列出同一次重发。

重发不跟随重定向、不使用环境代理，并在 30 秒后超时；请求的连接与传输头会重新生成，Content-Length 根据正文重新计算。截断、长度不一致或压缩编码的请求正文，以及 CONNECT / HTTPS 暂不支持重发。响应正文仍遵循 64 KiB 预览限制。

请求与响应的 Body 默认显示 **原文**，可随时切换。原文视图最多显示前 1 KiB，超出时提示，避免超大正文或二进制十六进制内容卡住界面。Content-Type 为 `application/json`（含 charset）或 `application/*+json` 时，可点击 **格式化** 启用 Pretty 缩进与语法高亮，支持行号、滚动与复制，保持只读。格式化不改变原始捕获内容；无效、截断或过深嵌套的 JSON 显示原文并提示。

Content-Type 为 `image/*` 时，Body 默认显示图片元信息（格式、尺寸、分辨率与大小），不展示二进制原文，工具栏只保留 **预览** 按钮，点击后按原始比例显示图片本身。解码失败或尺寸过大的图片不会展开，仅保留元信息与提示。

点击 Body 区域的 **全屏查看**，在独立全屏窗口中阅读当前正文。全屏中同样支持原文／格式化（图片仅预览）、滚动和复制，点击 **退出全屏** 或按 **Esc** 返回。全屏显示打开时选中消息的内容，使用独立的滚动与选择状态，不改变主界面的原文和视图模式。按钮对所有非空正文开放，长内容无需滚到底部即可打开。原文指捕获器提取的正文，现有 64 KiB 捕获限制仍适用。

页面顶部直接展示监听工具栏。通过 **帮助 → 关于 Webhola** 打开简介与版本弹窗。

### 扫描 HTTP 服务

点击 **扫描 HTTP 服务**，程序使用 Windows 原生接口枚举本机 TCP 监听地址、端口和进程，并通过短超时的 `HEAD /` 请求确认明文 HTTP/1.x 服务。扫描不依赖抓包驱动，最多并发 8 个探测，整体最长 30 秒，可随时点击“停止扫描”。不会自动扫描、不跟随重定向、不使用系统 HTTP 代理。

网卡下拉框优先显示适合本地 Web 调试的 WLAN、以太网和 Loopback；VPN、蓝牙、Hyper-V/WSL、VMware/VirtualBox、TAP/Wintun 等虚拟或辅助网卡排列在分隔线下方，仍可手动选择。

发现的服务按端口去重，同一个端口只显示一条，列表项显示端口、HTTP / JVM 类型、进程及 PID。同一进程的不同端口分别列出。选择一项即可设置 HTTP 端口，不再提供额外的端口或监听地址下拉框；网卡仍从“网卡”下拉框选择。内部保留同端口的所有监听地址，抓包只按所选网卡和 TCP 端口过滤。自动匹配规则为：

- 只有一个具体监听地址时，可根据地址匹配 loopback 或对应的网卡。
- 同端口有多个监听地址，或监听 `0.0.0.0` / `::` 时，保留当前网卡，不自动切到 loopback。局域网请求请选择 WLAN 或以太网，localhost 请求请选择 loopback。
- 初次刷新不猜测网卡。手动选择后，切换服务或刷新会保留仍然有效的网卡。重新扫描后恢复仍然存在的端口选择。
- 同端口属于多个进程时，不提供可能附加到错误进程的 JVM 跟踪入口。

仍可直接编辑“端口”；手动编辑会解除进程分组的选择，继续使用手动端口和当前网卡。监听期间禁止切换进程、端口、地址和网卡，先停止后再修改。扫描会产生实际请求并可能留下服务日志；HTTPS、要求特定 Host、启动较慢或不响应探测的服务可能不会列出，需手动配置。HTTP 401 / 404 / 405 等合法响应也会被识别为 HTTP。Windows 以外平台继续提供手动输入。

通过顶部 **文件 → 设置…** 菜单打开独立设置弹窗，当前仅配置可选的 JDK `java.exe`、`arthas-boot.jar` 与 Arthas HTTP 端口；抓包不再需要配置外部程序路径。底部保存／取消按钮固定显示，校验及写入成功后关闭弹窗并刷新网卡。设置保存在用户配置目录 `Webhola/settings.json`，下次启动自动读取。取消或直接关闭弹窗不会保存编辑内容。

Windows 实时抓包需要已安装的 Npcap；Npcap 的安装与许可由用户确认。

## 范围与限制

- 支持 HTTP/1.x 明文，不解密 HTTPS，不解析 HTTP/2、HTTP/3 或 WebSocket 升级后的消息。
- 只能看见所选网卡实际收到的流量。捕获前已建立的连接会被接管，从下一个完整 HTTP 起始行继续解析；开始抓包时正在传输的那条消息会被跳过。丢包、非对称路由也可能使请求／响应缺失；未匹配的响应不伪造为请求记录。
- 耗时从完整请求解析到完整响应接收计算，包含正文传输，不是浏览器 TTFB。
- Headers 与 Body 由内置 HTTP/1.x 解析器解码；Body 为实体正文，并非原始 TCP 字节流。二进制正文显示十六进制，单条预览限制 64 KiB，截断后仍消费剩余正文以保持消息边界。
- 最多保留最近 1000 条记录及 1000 条未完成请求。数据仅在内存中，不自动保存抓包文件；退出清除。TCP 重组和分片缓存均有上限，超出时丢弃对应连接或分片。
- Windows 复用已安装的 Npcap 并需要抓包权限；Linux 使用 AF_PACKET，需要 root 或 `CAP_NET_RAW`；macOS 使用系统 BPF，需要设备访问权限。Linux/macOS 尚未完成实机验证。

TCP 重组与 HTTP 解析能力来自 [gopacket](https://github.com/gopacket/gopacket) 与 Go 标准库 `net/http`。
