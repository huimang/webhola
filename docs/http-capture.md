# HTTP 抓包、服务发现与重发

本页记录现有桌面应用的详细行为和技术限制。基本操作见项目 README。

## HTTP 监听

使用 TShark 被动捕获指定网卡、指定 TCP 端口的明文 HTTP/1.x，借助其 TCP 重组能力分析请求和响应，不占用被监听端口、不设置系统代理。

左侧显示请求列表：方法、URL、时间、状态、耗时、正文大小，可按方法／URL／状态码／IP 搜索。选中后右侧显示请求与响应起始行、头部和正文，支持复制。保留临时响应，支持同连接上的多次请求与 IPv6。

每条记录提供 **重新发送** 按钮。点击后使用原方法、URL、Host、请求头（含 Cookie / Authorization）和捕获正文发起一次新的 HTTP 请求；原记录保留，新记录置顶并标记“重发”，显示响应、耗时或失败原因。停止监听后也可重发；监听期间通过连接地址避免被动抓包重复列出同一次重发。

重发不跟随重定向、不使用环境代理，并在 30 秒后超时；请求的连接与传输头会重新生成，Content-Length 根据正文重新计算。截断、长度不一致或压缩编码的请求正文，以及 CONNECT / HTTPS 暂不支持重发。响应正文仍遵循 64 KiB 预览限制。

请求与响应的 Body 默认显示 **原文**，可随时切换。Content-Type 为 `application/json`（含 charset）或 `application/*+json` 时，可点击 **格式化** 启用 Pretty 缩进与语法高亮，支持行号、滚动与复制，保持只读。格式化不改变原始捕获内容；无效、截断或过深嵌套的 JSON 显示原文并提示。

点击 Body 区域的 **全屏查看**，在独立全屏窗口中阅读当前正文。全屏中同样支持原文／格式化、滚动和复制，点击 **退出全屏** 或按 **Esc** 返回。全屏显示打开时选中消息的内容，使用独立的滚动与选择状态，不改变主界面的原文和视图模式。按钮对所有非空正文开放，长内容无需滚到底部即可打开。原文指捕获器提取的正文，现有 64 KiB 预览限制仍适用。

页面顶部直接展示监听工具栏。通过 **帮助 → 关于 Webhola** 打开简介与版本弹窗。

### 扫描 HTTP 服务

点击 **扫描 HTTP 服务**，程序使用 Windows 原生接口枚举本机 TCP 监听地址、端口和进程，并通过短超时的 `HEAD /` 请求确认明文 HTTP/1.x 服务。扫描不依赖 TShark / Npcap，最多并发 8 个探测，整体最长 30 秒，可随时点击“停止扫描”。不会自动扫描、不跟随重定向、不使用系统 HTTP 代理。

发现的服务按端口去重，同一个端口只显示一条，列表项显示端口、HTTP / JVM 类型、进程及 PID。同一进程的不同端口分别列出。选择一项即可设置 HTTP 端口，不再提供额外的端口或监听地址下拉框；网卡仍从“网卡”下拉框选择。内部保留同端口的所有监听地址，抓包只按所选网卡和 TCP 端口过滤。自动匹配规则为：

- 只有一个具体监听地址时，可根据地址匹配 loopback 或对应的网卡。
- 同端口有多个监听地址，或监听 `0.0.0.0` / `::` 时，保留当前网卡，不自动切到 loopback。局域网请求请选择 WLAN 或以太网，localhost 请求请选择 loopback。
- 初次刷新不猜测网卡。手动选择后，切换服务或刷新会保留仍然有效的网卡。重新扫描后恢复仍然存在的端口选择。
- 同端口属于多个进程时，不提供可能附加到错误进程的 JVM 跟踪入口。

仍可直接编辑“端口”；手动编辑会解除进程分组的选择，继续使用手动端口和当前网卡。监听期间禁止切换进程、端口、地址和网卡，先停止后再修改。扫描会产生实际请求并可能留下服务日志；HTTPS、要求特定 Host、启动较慢或不响应探测的服务可能不会列出，需手动配置。HTTP 401 / 404 / 405 等合法响应也会被识别为 HTTP。Windows 以外平台继续提供手动输入。

通过顶部 **文件 → 设置…** 菜单打开独立设置弹窗，浏览选择 `tshark.exe`，点击右下角 **保存**。底部保存／取消按钮固定显示；校验及写入成功后关闭弹窗并自动刷新网卡。路径保存在用户配置目录 `Webhola/settings.json`，下次启动自动读取。取消或直接关闭弹窗不会保存编辑内容。留空恢复自动发现。自定义路径优先于环境变量、PATH 和 Program Files/Wireshark。

也可通过环境变量临时指定位置：

```powershell
$env:WEBHOLA_TSHARK = 'D:\tools\Wireshark\tshark.exe'
./native/build/Webhola.exe
```

## 范围与限制

- 支持 HTTP/1.x 明文，不解密 HTTPS，不解析 HTTP/2、HTTP/3 或 WebSocket 升级后的消息。
- 只能看见所选网卡实际收到的流量。抓包中途加入、丢包、非对称路由可能使请求／响应缺失；未匹配的响应不伪造为请求记录。
- 耗时从 TShark 识别出完整请求到完整响应计算，包含正文传输，不是浏览器 TTFB。
- Headers 为 TShark 解码出的头部；Body 为解码出的实体正文，并非原始 TCP 字节流。二进制正文显示十六进制，单条预览限制 64 KiB。
- 最多保留最近 1000 条记录及 1000 条未完成请求。数据仅在内存中，不自动保存抓包文件；退出清除。TShark 的 TCP 重组缓存仍受其自身实现和流量规模影响。
- Windows 需要可用的 Npcap 与网卡抓包权限。macOS/Linux 需自行准备 TShark 与相应权限，尚未完成实机验证。

TShark 参数与重组行为参考 [官方手册](https://www.wireshark.org/docs/man-pages/tshark.html)。
